# 模型采样参数调优手册（对话 / RP 向）

> 目标：让角色对话更"像角色"——风格稳定、不跑题、不复读。
> 本文档只讲**采样参数**（模型生成时的随机性控制），不涉及提示词。
> 适用本项目所有 model profile（openai_compatible / ollama 两系）。

---

## 0. 先理解：采样在做什么

模型生成每个 token 时，会给整个词表打一个概率分布。**采样参数 = 从这个分布里"挑一个"的方式**：

```
分布形状（温度）→ 截断范围（top_p / top_k / min_p / tfs）→ 偏好修正（各种 penalty）→ 挑出最终 token
```

- **改形状**：temperature / mirostat
- **砍尾部**：top_p / top_k / min_p / tfs_z（防止低概率烂 token 被选中）
- **改偏好**：repetition_penalty / presence_penalty / frequency_penalty

一句话原则：**RP 要"稳"——温度偏低 + 适度惩罚复读 + 砍掉烂尾部；但别卡死，否则角色变成复读机里的机器人。**

## 1. OpenAI 系参数（doubao / deepseek 等 openai_compatible）

| 参数 | 类型/范围 | 作用 | RP 推荐起点 |
|---|---|---|---|
| `temperature` | float 0~2 | 分布"压扁/拉尖"。低=保守稳，高=发散跳 | 0.6 ~ 0.8（默认 1 偏发散） |
| `top_p` | float 0~1 | 核采样：只保留累积概率 ≤ top_p 的 token 参与采样 | 0.85 ~ 0.95；**和 top_k 二选一** |
| `max_tokens` | int | 单次回复最大 token 数 | 按需（本项目默认 2048） |
| `presence_penalty` | float -2~2 | 对**出现过的 token** 给固定惩罚 → 鼓励提新词、新话题 | +0.3 ~ +0.6（防绕同一个梗） |
| `frequency_penalty` | float -2~2 | 对**高频出现**的 token 惩罚**递增** → 抑制复读句式/口头禅 | +0.3 ~ +0.5 |
| `seed` | int | 固定随机种子，同输入可复现 | 调试用；不要在生产固定 |

> ⚠️ **火山引擎 / 豆包实测注意**：多数情况下**只认** `temperature / top_p / max_tokens`，`presence_penalty / frequency_penalty / seed` 可能被忽略或直接报 400。接入前先 curl 单测。

## 2. Ollama 系参数（本地模型，如 talker 的 llama3.1:8b）

| 参数 | 类型/范围 | 作用 | RP 推荐起点 |
|---|---|---|---|
| `temperature` | float 0~2 | 同上 | 0.6 ~ 0.8 |
| `top_k` | int 0~100 | 只从概率最高的 K 个 token 里采样（0=关闭） | 40（默认）或 20~30 更稳 |
| `top_p` | float 0~1 | 同上 | 0.85 ~ 0.95，**与 top_k 二选一** |
| `min_p` | float 0~1 | **相对阈值**：保留概率 ≥ 最大概率 × min_p 的 token | **0.05 ~ 0.1**（比 top_p 更聪明，不误伤小概率但有意义的词） |
| `tfs_z` | float 0~1 | tail-free：按概率二阶导裁剪尾部（1.0 = 关闭） | 0.9 ~ 0.95 |
| `mirostat` | int 0/1/2 | 动态熵控制：自动调温度稳住风格（0=关） | 弱模型救星：`mirostat=1, mirostat_tau=5, mirostat_eta=0.1` |
| `mirostat_tau` | float | 目标熵（mirostat 生效时） | 5.0 常见 |
| `mirostat_eta` | float | 熵调整学习率（mirostat 生效时） | 0.1 |
| `repetition_penalty` | float 0~2 | 对已出现 token 的概率打折（<1 鼓励，>1 惩罚） | **1.1 ~ 1.3** |
| `repeat_last_n` | int | 重复惩罚的回看窗口（多少 token 内算"重复"） | 64（默认） |
| `num_ctx` | int | 上下文窗口长度 | 按需（越长越吃显存） |
| `num_predict` | int | 单次生成最大 token 数（≈ max_tokens） | 按需 |
| `seed` | int | 固定种子 | 调试用 |

> `top_p / min_p / tfs_z` 三者机理接近（都在砍采样候选集），**一次只开一个**，混用会过度收紧导致输出干瘪。

## 3. 组合思路（不是越多越好）

### 3.1 OpenAI 系推荐起点

```json
{
  "temperature": 0.7,
  "top_p": 0.9,
  "presence_penalty": 0.4,
  "frequency_penalty": 0.3
}
```

- `presence + frequency` 双惩罚对 RP 非常有效：**presence 防止反复绕话题，frequency 防止复读句式**。
- 若平台不支持双惩罚，退化成 `temperature 0.7 + top_p 0.9`。

### 3.2 Ollama 系推荐起点（本地弱模型）

```json
{
  "temperature": 0.7,
  "top_p": 0.9,
  "repetition_penalty": 1.2,
  "repeat_last_n": 64
}
```

弱模型（llama3.1:8b 级别）若还是复读/跑题，二选一加码：

```json
{ "tfs_z": 0.95 }
```
或
```json
{ "mirostat": 1, "mirostat_tau": 5, "mirostat_eta": 0.1 }
```

### 3.3 参数过大 / 过小的典型症状

| 症状 | 原因 | 修法 |
|---|---|---|
| 复读、绕圈、句式僵化 | 温度过低 / 惩罚过高 / 截断过紧 | 温度 +0.1，或 penalty -0.1，或 top_p 放大 |
| 跑题、语气漂移、说胡话 | 温度过高 / 无惩罚 | 温度降到 0.7 以下，加 repetition_penalty |
| 输出干瘪、不敢写细节 | 截断过多（top_k 太小 / min_p 太高 / tfs 太紧） | 放松截断：top_k≥30，min_p≤0.1 |
| 同一句话反复说 | frequency_penalty / repetition_penalty 不够 | 上调 0.1~0.2 |
| 每次回复都不同（风格抖） | 随机性整体偏高 | 温度 0.6，必要时 seed 固定调试 |

## 4. 本项目如何传参（重要）

### 4.1 统一写法（v14 起，推荐）

**你只需在 `model_params` 顶层写规范参数名**，model-proxy 按 provider 自动适配重排（不用再管 `options` 包装、不用管命名差异）：

| 统一键（写这些） | ollama 自动变成 | openai_compatible 自动变成 |
|---|---|---|
| `num_ctx` / `num_predict` | 进 `options` | 不支持的忽略；`num_predict` 转 `max_tokens` |
| `repetition_penalty`（或旧名 `repeat_penalty`） | 进 `options` | 不支持，忽略 |
| `temperature` / `top_p` | 进 `options` | 顶层 |
| `top_k` / `min_p` / `tfs_z` / `mirostat*` | 进 `options` | 不支持，忽略 |
| `presence_penalty` / `frequency_penalty` | 不支持，忽略 | 顶层 |
| `max_tokens` | 自动转 `num_predict` | 顶层 |
| `seed` | 进 `options` | 顶层 |
| 其他自定义键 | 原样透传 | 原样透传 |

```json
// ollama（talker）——顶层直接写，不用 options 包装
"model_params": {
  "temperature": 0.7, "top_p": 0.9, "repetition_penalty": 1.2,
  "num_ctx": 8192, "num_predict": 2048
}

// openai（deepseek/doubao）——同一套键
"model_params": {
  "temperature": 0.7, "top_p": 0.9,
  "presence_penalty": 0.4, "frequency_penalty": 0.3
}
```

向后兼容：旧配置里 ollama 的 `options` 包装写法、`repeat_penalty` 旧名，都会被自动吸收重排，不用改。

### 4.2 覆盖顺序

`profile.model_params`（模型默认）→ `profile.temperature/max_tokens`（顶层默认）→ agent 配置透传值（请求级覆盖，agent_runtime v68 白名单）。

agent 级覆盖示例（`agent_list.json`）：

```json
{
  "default": {
    "agents": {
      "lilith": {
        "model_profile": "h268-imitator",
        "temperature": 0.7,
        "top_p": 0.9,
        "presence_penalty": 0.4,
        "frequency_penalty": 0.3
      }
    }
  }
}
```

## 6. 调试方法论

1. **单变量法**：一次只改一个参数，跑 3~5 轮同样的开场白，对比风格。
2. **固定 seed 定位**：先固定 seed 复现问题（是参数问题还是模型抽风），再放开。
3. **先惩罚后温度**：RP 效果贡献排序大约是 `repetition_penalty/presence+frequency > temperature > top_p/top_k/min_p`，先调前者。
4. **每模型一套**：不同模型对同一参数响应完全不同（豆包和 llama3.1 的 top_p 手感就不同），不要跨模型套用结论。
5. **留记录**：每套参数存到 agent_list.json 前先记下"改动 + 观察"，方便回退。
